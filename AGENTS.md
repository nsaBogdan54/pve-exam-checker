# AGENTS.md — Система автоматизированной проверки экзаменационного стенда (Модуль 1)

## 1. Назначение и архитектура проекта
Проект представляет собой модульный комплекс на Python для автоматизированного сбора конфигураций и объективной оценки выполнения **Модуля 1** демонстрационного экзамена в среде виртуализации **Proxmox VE**.

Проверка разделена на два независимых этапа:
1. **Сбор данных (`collector.py`)** — подключается к Proxmox VE API, снимает актуальное состояние со всех 7 виртуальных машин стенда и сохраняет текстовый слепок в `dumps/<ИМЯ_ПУЛА>/latest_<ИМЯ_ПУЛА>.txt`.
2. **Анализ и оценка (`check.py` + `tasks/*.py`)** — парсит собранный дамп без повторного обращения к виртуальным машинам и формирует детальный отчёт по всем 11 пунктам задания.

## 2. Структура файлов
```text
/root/
├── AGENTS.md              # Документация проекта и описание архитектуры

├── collector.py           # Модуль сбора конфигураций и сетевого состояния с ВМ
├── check.py               # Главный управляющий скрипт (CLI-интерфейс проверки)
├── dumps/                 # Архив собранных дампов, сгруппированный по пулам студентов
│   └── <PoolName>/
│       └── latest_<PoolName>.txt
└── tasks/                 # Независимые модули проверки по пунктам задания
    ├── __init__.py
    ├── parser.py          # Парсер конфигураций EcoRouterOS и вывода Linux-узлов
    ├── p1_base.py         # Пункт 1: FQDN, приватность IPv4, маски подсетей (/27-/30), шлюзы
    ├── p2_nat.py          # Пункт 2 и 8: IP-форвардинг, NAT (iptables/nftables и EcoRouter)
    ├── p3_users.py        # Пункт 3: Локальные учетные записи (sshuser UID 2027, sudo, net_admin)
    ├── p4_ssh.py          # Пункт 5: Настройка SSH (порт 2027, AllowUsers, MaxAuthTries, баннер)
    └── p_services.py      # Пункты 4, 6, 7, 9, 10, 11: VLAN, GRE /30, OSPF+MD5, DHCP, DNS, время
```

## 3. Механизм безопасного взаимодействия со стендом
Система спроектирована так, чтобы **не требовать `root`-доступа к гипервизорам (`PVE1`/`PVE2`)**, не зависеть от ошибок студентов в сетевой адресации и не оставлять следов после проверки:

* **Linux-узлы (`ISP`, `HQ-SRV`, `HQ-CLI`, `BR-FW`, `BR-SRV`):**
  Опрашиваются напрямую через Proxmox API (`POST /nodes/{node}/qemu/{vmid}/agent/exec`) с использованием `qemu-guest-agent`. Это позволяет считывать состояние даже при полностью неработающей сети или изменённых портах SSH.
  * *Примечание по шаблонам:* В базовых шаблонах `ALT p11` (`ISP`, `BR-FW`) перед развёртыванием стендов должен быть предустановлен и включён пакет `qemu-guest-agent`.
* **Маршрутизаторы `EcoRouter` (`HQ-RTR`, `BR-RTR`):**
  Для каждого роутера по очереди через API временно подключается изолированный интерфейс управления `net0` (`vrf management`, `192.168.255.1/24` в `vmbr0`), снимается `show running-config` и `show users localdb` по SSH (`paramiko`), после чего в блоке `try...finally` гарантированно возвращается флаг `link_down=1` и удаляется временный IP с проверяющей ВМ.

## 4. Требования к правам доступа (Proxmox VE)
Для работы сервисной учётной записи (`ExamChecker@pve`) без выдачи полных прав администратора кластера необходимы следующие привилегии:
* На `/vms`: `VM.Audit`, `VM.Monitor`, `VM.Config.Network`
* На `/sdn`: `SDN.Use`
* На `/pool`: `Pool.Audit`

## 5. Инструкция по запуску

### Полная проверка пула студента (сбор свежих данных + оценка)
```bash
python3 check.py <ИМЯ_ПУЛА>
# Пример:
python3 check.py MinorovBP
```

### Повторная оценка без обращения к ВМ (по сохранённому дампу)
```bash
python3 check.py <ИМЯ_ПУЛА> --offline
```

### Точечная проверка отдельного блока задания
```bash
python3 check.py <ИМЯ_ПУЛА> --offline --only p1
# Доступные ключи: p1, p2, p3, p5, services
```

## 6. Ключевые особенности логики проверки
* **Независимость от конкретных IP-адресов:** В Пункте 1 проверяются не жёстко заданные адреса, а принадлежность к диапазонам RFC 1918, соответствие префиксов требованиям задания (`<= /27` для VLAN 100, `<= /28` для VLAN 200 и BR-SRV, `<= /29` для VLAN 999, строго `/30` для стыка `BR-RTR — BR-FW` и GRE-туннеля) и связность стыков.
* **Независимость от DNS-реализации:** В Пункте 10 проверяется доступность 53-го порта на `HQ-SRV` и реальное разрешение прямых (`A`), обратных (`PTR`) и внешних доменных имён с клиентских и серверных узлов через системный резолвер (поддерживаются как `BIND`, так и `dnsmasq`).
* **Точный парсинг без комментариев:** Для проверки прав `sudo` используется вывод `sudo -l -U sshuser`, а для параметров SSH — активная конфигурация демона `sshd -T` с автоматическим чтением файла баннера по указанному в конфигурации пути.
